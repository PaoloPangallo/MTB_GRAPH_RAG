# Documentary findings presentation

The research console presents target relations, literal quotations, Reader-extracted
observations, recorded checks and limitations separately. It does not compute a new
scientific verdict from FULL_SUPPORT, PARTIAL_SUPPORT or CONTRADICTORY.

Historical backend classifications remain available in technical details and raw
artifacts. Original narrative prose is retained in explicitly labelled disclosure
sections; existing verification-PASS requirements still govern its availability.
The subsequent coherence sprint adds `documentary-findings/1.0` to newly built
canonical dossiers, with the same facts used in controlled narrative, Markdown
and API schemas. Existing stored runs retain their original contract. Internal
admission adapters still preserve their historical labels for compatibility;
these do not define the new scientific endpoints or technical completeness.

Quotation authentication is not scientific validation. Reader-extracted intervention,
molecular subjects, result direction and experimental context are identified as
extractions, not independently established facts. Missing checks remain unrecorded;
unexecuted semantic assessments and technical errors are displayed separately.
Publication and reconciliation states remain exactly those recorded by the backend.

The summary counts retained records and distinct source identifiers separately from
target relations. Distinct identifiers are not a bibliographic identity-resolution
claim: PMID and PMCID aliases are not merged without an explicit mapping.

Validation: run `npm run build`, `npm run lint`, and targeted Vitest tests for
`documentaryFindings`, `DossierView`, `NarrativeView`, stages and architecture.
No provider calls are required. Scientific framework:
`../docs/evaluation/11_documentary_findings_framework_20261014.md`.
